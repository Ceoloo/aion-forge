# Forge v0.2 trust boundary — REVIEW ARTIFACT, NOT LIVE CONNECTIVITY

The existing AION Sentinel verifier verifies Keycloak RS256 access tokens, fixed issuer/audience/azp, expiry, and exact durable issuer/subject/client binding in AION Data. The Forge adapter MUST receive this trusted verifier; Forge must not implement a second JWT authority or accept untrusted identity headers.

The identity adapter obtains a single request-scoped credential, calls verifyIdentity({credential}), enforces Runtime Principal shape, and returns that principal with a non-enumerable same-request Runtime bearer. Runtime independently verifies the same bearer and reloads the durable Actor/grants. No token roles or request-body grants.

The durable audit adapter accepts only allowlisted metadata: requestId, tenantId, principalId, actorId, workspaceId, template, status, runId, executionId. Never raw commands, terminal output or credentials. Event identifiers are deterministic for idempotent retries, and a committed acknowledgment must be returned by the Data-owned writer before Runtime is called.

## Trusted Runtime-owned composition (illustrative, not runnable standalone)

    const lookupPrincipal = createRuntimePrincipalLookup({
      getBinding: identityBindings.getActive.bind(identityBindings),
      getActor: actors.get.bind(actors)
    });
    const verifyIdentity = createKeycloakVerifier({
      issuer, audience, allowedClients, lookupPrincipal
    });
    const identity = createSentinelIdentityAdapter({
      verifyIdentity, credentialProvider: requestScopedCredential
    });
    const audit = createDurableAuditAdapter({
      write: (event) => dataLayer.forgeAudit.append(event)
    });
    const runtime = createRuntimeClient({
      baseUrl: runtimeOrigin, requireBoundCredential: true
    });

The Data forgeAudit repository and Runtime-owned trusted transport are NOT yet in a merged/staged platform release. Forge product code must never import Data or query PostgreSQL directly. The adapter ports are designed for trusted Runtime-side composition. A mocked writer ACK is not durability proof.

## Mandatory gates

2. Apply migration 0015 in disposable staging through authorized migrator; prove app role has SELECT only on identity bindings.
3. Add Data-owned Forge audit schema and repo, with append-only permissions, idempotency, tenant isolation and real PostgreSQL tests.
4. Wire Runtime-owned identity/Actor/audit transport without creating a second execution gateway.
5. Prove staging request and failure traces before any Forge execution capability registration, isolated workers or Herdr launch.

Current code implements contract adapters and mock-backed tests, not live cryptographic tests or deployed storage. Production and existing GE-001/AIO-111 gates remain unchanged.
